# ViewX Studio

Web 畫面規劃工具：**TypeScript + React 前端、C# + ASP.NET Core 後端、SQLite 儲存**。瀏覽器執行使用模擬資料，無須舊 `.vxf` 或原有 HMI。

## 必要工具

- Node.js **24 以上**（前端工具與測試）。
- **.NET 10 SDK**（不是只有 Runtime）。`dotnet --version` 應顯示 `10.0.x`；SDK 選擇由 `global.json` 管理。

以下指令都在儲存庫根目錄執行，可用於 Windows PowerShell、macOS 與 Linux。

## 開發模式

第一次準備：

```sh
npm ci
dotnet restore server/ViewX.Server.csproj --locked-mode
```

開兩個終端機：

```sh
# 終端機 1：C# API，port 5000
npm run dev:server
# 等同 dotnet run --project server/ViewX.Server.csproj
```

```sh
# 終端機 2：React / Vite，port 3000
npm run dev
```

瀏覽器開啟 **http://localhost:3000**。Vite 將 `/api` 請求轉送至 C# 的 http://localhost:5000，因此不需要設定 CORS。儲存時若顯示連線失敗，先確認 API 終端機已啟動。

## 單一服務執行

```sh
npm ci
npm run build
npm start
```

`npm start` 使用 C# 同時提供建置後的網頁與 API，瀏覽器開啟 **http://localhost:3000**；不需要啟動 Vite。這個指令沒有使用 Bash 環境變數語法，可在 Windows 執行。

若只需要 C# 後端，可直接執行 `dotnet run --project server/ViewX.Server.csproj`。正式網頁需先 `npm run build`。

## 發布

```sh
npm run build
npm run publish:server
```

輸出位於 `artifacts/server`，包含前端 `wwwroot` 及 C# 伺服器。部署機器需要 .NET 10 ASP.NET Core Runtime，前端建置完成後不再需要 Node.js。

```sh
cd artifacts/server
dotnet ViewX.Server.dll --urls http://localhost:3000
```

## 功能與手動測試

- 檔案、編輯、檢視、畫面、元件、排列、變數、執行、說明選單。
- 多畫面管理、起始畫面設定、10 種基本元件及 4 種進階元件。
- 拖拉、調整尺寸、多選、對齊、群組、圖層、鎖定、格線、復原／重做。
- 在空白畫布按住左鍵拖曳框選完整落入範圍的可見元件；Shift 框選追加選取，Esc 取消。群組元件一起選取，鎖定元件可選取但不會移動。
- 編輯模式右鍵點擊元件，開啟屬性視窗；修改即時套用，按完成、Esc 或點擊視窗外關閉，關閉後可復原。預覽／執行模式不開啟屬性編輯。
- 數值／布林／文字變數、資料綁定、顯示／啟用條件、模擬值監看。
- SQLite 專案保存、版本紀錄、版本衝突保護、JSON 匯入／匯出。

首次開啟會顯示尚未儲存的示範產線：按「執行專案」→「啟動／停止」，指示燈應改變；按「＋計數」，數值應增加。停止後新增元件、修改屬性、儲存，再從專案清單重開確認設定保留。

## 基本元件外觀設定

選取元件後可在右側屬性面板設定，或以右鍵開啟元件屬性視窗。修改即時套用並支援復原／重做，儲存後重開可保留設定。

| 元件       | 可設定功能                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------- |
| 文字       | 多行文字、字型、字型大小、粗體、斜體、底線、水平／垂直對齊、自動換行、行距、文字／背景色；可綁定變數顯示內容。 |
| 矩形／圓形 | 邊框顏色、線寬、實線／虛線／點線／無邊框、背景填色；矩形可調整圓角。                                           |
| 直線       | 線條顏色、線寬與線型。                                                                                         |
| 圖片       | 等比例完整顯示、等比例填滿裁切、拉伸填滿、原始尺寸裁切，及圖片對齊位置；可更換或移除圖片。                     |
| 按鈕       | 一般、滑鼠移入、按下、停用的背景／文字色；邊框、圓角與既有互動動作。                                           |

按鈕在預覽中可測試移入與按下外觀，停用狀態由「啟用條件（布林）」控制；停用時不執行動作。字型使用裝置上已安裝的字型，未安裝時使用替代字型。文字超出元件範圍會裁切；取消自動換行仍保留手動輸入的換行。

新外觀欄位為可選設定，既有 schema-v1 專案可直接開啟，不需轉換資料庫。

## 資料與互動設定

- **數值顯示**：小數、整數四捨五入、百分比、科學記號；小數位數留白時最多顯示 3 位，也可指定 0–6 位、千分位、前綴、單位及英文／臺灣／德文數字格式。百分比將原值乘以 100 顯示，0.125 顯示為 12.5%。
- **數值輸入**：可設定最小值、最大值與正數步距，留白表示不限制。步距起點為最小值，未設定則為 0。預覽時先編輯暫存文字，按 Enter 或離開欄位才寫入；Esc 取消。空白、非有限數值、超限或不符合步距時顯示原因並還原原值，不寫入變數。啟用條件為 false 時停用輸入。
- **變數綁定**：數值元件只列數值變數，指示燈／開關／切換動作只列布林變數；文字、設定值及重設動作支援三種類型。失效綁定、類型不符、條件或目標畫面失效會顯示診斷並阻止預覽／執行。
- **按鈕動作**：切換布林、設定數值／布林／文字、正負數加減、重設綁定變數為初始值、切換畫面。布林設定使用 TRUE／FALSE 清單；數字設定不能留白，也不接受 Infinity 或溢位結果。切換動作時自動挑選適用類型的變數，設定值動作更換綁定時使用該變數初始值，請確認設定值後再執行。

範圍與步距限制屬於各輸入元件，不是變數的全域限制；模擬值監看與其他按鈕動作仍可修改同一變數。專案檢查也確認輸入元件的初始值符合限制。可保存尚未完成綁定的專案草稿，預覽／執行前須修正診斷；欄位格式錯誤（例如步距為 0）則不能儲存。模擬互動只修改執行值，重新開始模擬時回到專案初始值。

## 進階元件

在元件庫新增「儀表」、「長條顯示」、「趨勢圖」或「警報清單」，再透過右側面板或右鍵屬性視窗設定。

| 元件     | 設定與行為                                                                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 儀表     | 數值綁定、量程、數值格式、資料／軌道顏色、警戒／危險門檻、顯示值與刻度；以半圓指針及弧線顯示。                                                                                  |
| 長條顯示 | 數值綁定、量程與門檻顏色，支援水平或由下往上的垂直方向。                                                                                                                        |
| 趨勢圖   | 數值綁定、Y 軸量程、顏色、100–60,000 ms 取樣間隔、10–600 個保留點；編輯時顯示示意曲線，預覽時依實際模擬值取樣。                                                                 |
| 警報清單 | 每個元件最多 20 項規則，支援數值的 >／≥／<／≤／=／≠ 比較及布林 TRUE／FALSE 條件；可設定訊息、資訊／警告／嚴重等級及規則啟用狀態。顯示筆數 1–100，支援「只看發生中」與逐筆確認。 |

儀表與長條達到警戒門檻顯示橙色，達到危險門檻顯示紅色。超出量程時圖形停在端點，數值仍顯示原值；趨勢線也限制在 Y 軸量程內。最大量程必須大於最小量程，門檻必須在量程內，警戒門檻不可大於危險門檻。

趨勢與警報會監看整個專案，切換畫面不會中斷取樣或遺漏該段警報。持續符合條件只產生一筆警報，條件恢復時標示「已解除」，再次觸發則新增一筆。確認只表示已閱讀，不會解除仍存在的條件。保留所有發生中警報及最近發生的最多 1,000 筆已解除紀錄。

目前資料源為本機模擬變數，可在執行狀態面板修改值測試。專案儲存保留元件與規則設定；趨勢點及警報紀錄只保留在本次模擬中，停止、重新開始、重設模擬或重新整理頁面會清除，尚未寫入歷史資料庫。參照警報規則的變數也受刪除保護，須先刪除或解除規則綁定。

## 自動測試

```sh
npm run build
npm test
npm run test:server
npm run test:api
npx playwright install chromium
npm run test:browser
npm run test:widgets
npm run test:interactions
npm run test:advanced
npm run test:dev
```

- `npm test`：前端 JSON 資料格式、數值格式、輸入限制、綁定及動作規則驗證。
- `npm run test:server`：C# 驗證器、SQLite 保存／版本及並行寫入測試。
- `npm run test:api`：以舊 Node.js 建立的 SQLite 檔案驗證 C# 讀寫相容性、重啟保存、驗證器一致性、HTTP 狀態、請求大小限制及靜態網頁。
- `npm run test:advanced`：四種進階元件設定／重開、量程與警戒色、跨畫面及有上限的趨勢取樣、警報發生／確認／解除／再觸發、模擬重設與無效設定檢查。
- `npm run test:interactions`：數值格式設定、綁定篩選、輸入確認／範圍／步距／取消／停用、各類按鈕動作、診斷與儲存重開。
- `npm run test:widgets`：文字格式與變數綁定、圖形邊框、圖片縮放、按鈕停用／移入／按下外觀，以及設定儲存重開。
- `npm run test:browser`：透過 C# 後端實際測試編輯、模擬、儲存／重開、匯入／匯出及畫面切換。

`npm run test:dev` 另驗證 Vite 開發代理及前後端分開啟動時的儲存／重開流程。

整合與瀏覽器測試會自行啟動隔離 C# 服務並使用暫存 SQLite，不修改使用者的專案資料。可用 `VIEWX_BROWSER_PATH` 指向已安裝的 Chromium；若 `dotnet` 不在 PATH，可設定 `VIEWX_DOTNET_PATH`。

## 既有資料與設定

原本 `.data/viewx.db` **直接沿用**；`projects`、`versions` 資料表與 JSON 格式不變，不需要轉換或刪除資料。每次儲存會增加版本；過期版本寫入回傳 HTTP 409。圖片仍內嵌於 JSON，單張上限 3 MB，請求上限 20 MB。

| 設定                  | 說明                                                                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `VIEWX_DB_PATH`       | SQLite 檔案路徑；預設為儲存庫的 `.data/viewx.db`，發布後為執行目錄的 `.data/viewx.db`。相對路徑依 C# 工作目錄解析，建議使用絕對路徑。 |
| `VIEWX_API_URL`       | Vite 開發代理的後端位置；預設 `http://localhost:5000`。                                                                               |
| ASP.NET Core `--urls` | C# 監聽位址，例如 `dotnet run --project server/ViewX.Server.csproj --no-launch-profile -- --urls http://localhost:5100`。             |

舊 Node.js 的 `HOST`、`PORT`、`NODE_ENV` 不再用於啟動後端。健康檢查仍為 `GET /api/health`，回傳 `{ "status": "ok", "storage": "sqlite" }`。

資料庫不納入 Git。備份應使用 SQLite Online Backup API 或關閉服務後備份；運行中不要僅複製 `.db` 而忽略 WAL 資料。發布產物不包含專案資料，部署時須保留／指向原有資料庫。

## 前端程式結構

`src/App.tsx` 只負責組合介面與提供編輯器 context，各項功能依職責拆分：

| 目錄                                  | 職責                                                                               |
| ------------------------------------- | ---------------------------------------------------------------------------------- |
| `components/widgets`                  | 14 種元件各自的 React 呈現與執行互動，透過 `WidgetRenderer` 統一呼叫。             |
| `registry/widgetRegistry.ts`          | 元件名稱、圖示、React 元件及建立函式的登錄表。                                     |
| `components/editor`                   | 工具列、選單、畫面編輯區、左側清單、屬性面板與檔案輸入。                           |
| `components/dialogs`、`components/ui` | 專案對話框及共用欄位、按鈕。                                                       |
| `hooks`                               | 選取／拖曳／縮放、復原／重做、模擬、快捷鍵、通知與專案保存；`useEditor` 協調流程。 |
| `context`                             | 將編輯器狀態與操作提供給各面板。                                                   |
| `services`                            | HTTP API、JSON 下載及專案檢查。                                                    |
| `types`、`utils`                      | 共用介面型別及專案複製、初始變數值。                                               |
| `model.ts`                            | 專案資料模型、預設元件及 JSON 格式驗證。                                           |

新增元件時，先在 `components/widgets` 建立獨立檔案，再加入元件登錄表。若新增元件種類或設定欄位，也需同步調整 `model.ts` 的型別、預設值與驗證、屬性面板及 C# `ProjectValidator.cs`；不需要將呈現程式加入 `App.tsx`。此拆分保留既有 JSON、SQLite 及操作行為。
