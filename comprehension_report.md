### What this proposes

This specification proposes upgrading `InfoSys_ViewGP_Web` to implement the user workflows from `AIS-47` and the CSS design tokens from `AIS-48` in a 100% backward-compatible manner that preserves existing runtime defaults, industrial safety constraints, and automated tests. Specifically, it adds: (1) an IndexedDB offline draft store (`offlineDraftStore.ts`) with recovery prompts, structured project version diffing (`projectDiff.ts`), version labeling, configurable auto-save intervals, and one-click SQLite database backup download; (2) optional transactional (`popupCommitMode: "transactional"`, which stages non-momentary variable changes in `popupDrafts` until confirmed via `confirmPopup`) and non-modal (`popupModal: false`) Popup dialog behaviors alongside configurable max popup nesting depth; (3) canvas smart alignment guides (`alignmentGuides.ts`), 100-step undo/redo that preserves element selection, expanded keyboard shortcuts (`Ctrl+G`, `Ctrl+Shift+G`, `Ctrl+L`, `Ctrl+D`), widget library Chinese alias search with recent/favorite quick-access chips, and a 3-step Project Wizard with 4 built-in industrial templates; (4) single-device Modbus connection testing (`POST /api/communication/test`), retention-based pruning of cleared alarm history (`POST /api/projects/{id}/alarm-events/prune`), and global status bar indicators for data freshness timestamps and pending queues; and (5) `:root` `--ds-*` CSS custom properties in `src/styles.css` with a view-menu toggle between the default `.engineering-shell` theme and the humanized light theme.

### How the existing system works, per this document

`InfoSys_ViewGP_Web` is a single-page web-based industrial HMI screen editor and monitoring system built with a TypeScript + React 19 frontend (using an LVGL v9 WebAssembly rendering core supporting 22 industrial widget types, orchestrated via hooks such as `useEditor`, `useSimulation`, and `useProjectPersistence`) and a C# ASP.NET Core (.NET 10) Minimal API backend (`Program.cs`, `ProjectStore`, `AlarmHistoryStore`, `CommunicationRuntime`) backed by a SQLite database (`.data/viewx.db` in WAL mode). Currently, projects use `schemaVersion: 1` validated symmetrically by `src/model.ts` on the frontend and `server/ProjectValidator.cs` on the backend, and unsaved new projects start at `revision === 0` without browser-side IndexedDB draft protection. In runtime/simulation mode, all Popup dialogs currently lock the background canvas (`inert`) and execute all widget writes and button actions immediately against variables/Modbus devices, while disabling write-capable controls whenever a Modbus device is offline, tag quality is not `"good"`, or a tag is read-only (never queuing offline PLC control writes for delayed replay). On the editor side, undo/redo history stores up to 50 steps and clears the active element selection on undo/redo, and the UI defaults to the compact `.engineering-shell` theme defined in `src/engineering.css` alongside hardcoded colors in `src/styles.css`.
