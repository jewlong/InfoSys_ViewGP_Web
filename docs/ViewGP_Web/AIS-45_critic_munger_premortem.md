## 0. 執行摘要

ViewGP（InfoSys_ViewGP_Web）是一款「超低成本嵌入式 HMI 網頁規劃與執行平台」：TypeScript + React 網頁設計器、C# + ASP.NET Core 後端、SQLite 儲存，匯出 `project.json` 直接於 Raspberry Pi Zero W / Zero 2 W 裸機 (µC/OS-II + LVGL 9.4) 執行，內建 Modbus TCP/COM 與警報引擎，目標市場為小型設備廠商、系統整合商與機台製造商，定價參考 SquareLine Studio 分層訂閱 ($66~$200/月)，不販售硬體。

本評估採用 **Pre-Mortem（事前檢驗）** 法：假設 12 個月後商業化失敗，倒推可能導致失敗的因素，並建立風險登記冊、產品層級風險揭露建議，以及 Phase 1 犬食測試 → Phase 2 對外商業化的 Go/No-Go 門檻。

**整體結論：** 商業化方向可行，但**不宜直接對外大規模收費**。必須先完成「登入權限、HTTPS、存取控制」三項安全門檻，並在產品層級明確揭露「無生產 SLA 保證」與「Pi Zero 裸機可靠性邊界」，否則極易因安全事件、現場停機或誤承諾 SLA 導致客戶流失、品牌受損與法律風險。

## 1. Pre-Mortem：假設 12 個月後商業化失敗，失敗原因會是什麼？

| # | 假設失敗場景 | 根本原因 | 對商業化的影響 | 預防關鍵動作 |
|---|---|---|---|---|
| PM-1 | 首批付費客戶部署後發生資料外洩或未授權操作，客戶下架並要求賠償 | 對外部署前未實作登入/HTTPS/存取控制；預設僅監聽 localhost，缺乏身分驗證 | 直接喪失信任，小型設備廠商與系統整合商不願採購，可能引發法律糾紛 | AIS-46 PRD 必須將登入/HTTPS/存取控制作為 MVP 必備；AIS-52 部署前強制 HTTPS |

## 3. 產品層級風險揭露：建議位置與標準措辭

CEO-Bezos 已決定「不承諾生產 SLA」，且產品對外部署前必須補登入/HTTPS/存取控制。以下風險揭露應落實在產品層級，而非僅靠口頭說明：

### 3.1 建議揭露位置
1. **產品/定價頁面**：定價表下方註記「不包含生產 SLA 保證」。
2. **使用條款與服務協議 (ToS)**：明確排除正常運行率、零停機、資料遺失之擔保。
3. **部署向導 / 首次對外部署時**：彈出確認對話，要求使用者勾選「已理解本系統為輕量嵌入式 HMI，不適合承擔生產 SLA」。
4. **project.json 匯出對話**：提醒「匯出後請定期備份 Pi Zero SD 卡與 project.json」。
5. **設備連線狀態列**：Modbus 斷線時顯示「設備連線異常」而非靜默顯示舊值。
6. **Pi Zero 執行階段說明書**：標註「消費級單板，非工業 24x7 持續運作設備，建議定期更換 SD 卡」。

### 3.2 標準措辭建議 (繁體中文)
> 「ViewGP 是一款輕量嵌入式 HMI 規劃與執行平台，執行終端建議使用 Raspberry Pi Zero W / Zero 2W 等消費級單板。**本系統不承諾任何生產等級正常運行率 (SLA) 或零停機保證**，亦不適合大型廠房全廠 SCADA 使用。對外部署前請務必啟用登入權限、HTTPS 與存取控制；Modbus 通訊中斷時系統會顯示「設備連線異常」。建議使用者定期備份 project.json 與 Pi Zero SD 卡。因終端可靠性邊界或通訊中斷導致之損失，概不負責。」

## 4. Go / No-Go 門檻：從 Phase 1 犬食測試 → Phase 2 對外商業化

### Phase 1 (內部驗證 / dogfood，現階段) 完成條件
- [ ] project.json 可正常匯出並於 Pi Zero W / Zero 2 W 裸機執行
- [ ] Modbus TCP/COM RTU 讀寫正確，斷線重連與讀回確認通過 (AIS-51)
- [ ] 警報引擎觸發正確，警報歷史存入 SQLite
- [ ] 使用者願意持續使用並回饋 (友好客戶或內部)
- [ ] **尚未對外收費，不承諾 SLA**

### Phase 2 (對外商業化) 進入門檻 (全部必須滿足)
- [ ] **登入權限、HTTPS、存取控制已實作並通過安全測試** (AIS-46 MVP 必備、AIS-52 部署)
- [ ] 產品層級風險揭露 (第 3 節) 已落實於 ToS、部署向導、產品頁面
- [ ] 合約/服務條款已排除生產 SLA 保證 (AIS-54/AIS-56)
- [ ] 獲客成本 (CAC) 與月費盈虛平衡點已驗證 (AIS-56)
- [ ] 首批付費客戶 (小型設備廠商/系統整合商) 完成單一客戶驗證

### Kill / 暫停條件 (任一觸發即停)
- 對外部署前仍未完成登入/HTTPS/存取控制
- 發生資料外洩或未授權存取事件
- 首批客戶因 Pi Zero 終端停機或 Modbus 可靠性問題要求退費
- 銷售人員承諾 SLA 且無法撤回

## 5. 戰略性排除 (再確認，與 AIS-44 對齊)

為避免商業化失敗，以下項目在 Phase 1~2 **明確不做**：
1. **大型廠房全廠 SCADA** — 與 Ignition/WinCC 等巨頭正面碰撞，無法勝出功能廣度；亦非 Pi Zero 定位。
2. **桌面軟體** — 網頁零安裝是核心差異化；桌面形式喪失遠端部署與多用戶 SaaS 便利。
3. **短期非 Modbus PLC 驅動** — 先把 Modbus 與警報引擎做穩，避免資源稀釋。
4. **設備正常運行 / 生產 SLA / 零停機保證** — 嵌入式終端可靠性有邊界，承諾 SLA 帶來法律責任與品牌風險；產品層級應做風險揭露而非承諾。
5. **公司直接販售 Pi Zero 硬體** — 避免硬體庫存與供應鏈風險，僅給建議規格。

## 6. 結論與建議

ViewGP 的商業化機會在於「超低硬體成本 (Pi Zero) + 網頁零安裝 + 免編譯 JSON 匯出 + 內建 Modbus 與警報引擎」，滿足小型設備廠商、系統整合商與機台製造商對嵌入式 HMI 的輕量化需求，且不直接與企業級 SCADA 正面碰撞。

**建議：** 核可本風險評估，並要求 AIS-46 PRD 將「登入/HTTPS/存取控制」列為 MVP 必備功能、將「無生產 SLA」寫入服務條款，並落實第 3 節的產品層級風險揭露。在單一友好客戶完成 dogfood 驗證前，不對外大規模商業化，不承諾任何生產 SLA。風險評估完成後，可與 AIS-46 PRD 並行進入 Phase 2 設計與架構。
