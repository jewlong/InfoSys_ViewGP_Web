# ViewGP

Web 畫面規劃工具：**TypeScript + React 前端、C# + ASP.NET Core 後端、SQLite 儲存**。預設離線模擬，也可由 C# 後端透過 Modbus TCP／COM RTU 讀寫設備，無須舊 `.vxf` 或原有 HMI。

## 操作手冊

第一次使用可先讀 [圖文操作手冊 PDF](docs/ViewGP-操作手冊.pdf) 第 2 章，依「泵浦監控」範例完成匯入、保存、離線執行與 Popup 操作。手冊包含 12 個操作章節、3 個附錄與 22 張實際畫面。

- [可編輯 Word](docs/ViewGP-操作手冊.docx)／[離線網頁版](docs/ViewGP-操作手冊.html)。
- [泵浦監控教學專案](docs/manual/examples/泵浦監控教學.json)：使用「檔案 → 匯入專案…」載入。
- [完整使用手冊套件](docs/ViewGP-使用手冊套件.zip)：一次取得各格式與教學專案。
- [手冊資源與重新產生方式](docs/manual/README.md)。

## 必要工具

- Node.js **24 以上**（前端工具與測試）。
- **.NET 10 SDK**（不是只有 Runtime）。`dotnet --version` 應顯示 `10.0.x`；SDK 選擇由 `global.json` 管理。

以下指令都在儲存庫根目錄執行，可用於 Windows PowerShell、macOS 與 Linux。

## 開發模式

第一次準備：

```sh
npm ci
dotnet restore server/ViewX.Server.csproj --locked-mode
```

開兩個終端機：

```sh
# 終端機 1：C# API，port 5000
npm run dev:server
# 等同 dotnet run --project server/ViewX.Server.csproj
```

```sh
# 終端機 2：React / Vite，port 3000
npm run dev
```

瀏覽器開啟 **http://localhost:3000**。Vite 將 `/api` 請求轉送至 C# 的 http://localhost:5000，因此不需要設定 CORS。儲存時若顯示連線失敗，先確認 API 終端機已啟動。

## 單一服務執行

```sh
npm ci
npm run build
npm start
```

`npm start` 使用 C# 同時提供建置後的網頁與 API，瀏覽器開啟 **http://localhost:3000**；不需要啟動 Vite。這個指令沒有使用 Bash 環境變數語法，可在 Windows 執行。

若只需要 C# 後端，可直接執行 `dotnet run --project server/ViewX.Server.csproj`。正式網頁需先 `npm run build`。

## 發布

```sh
npm run build
npm run publish:server
```

輸出位於 `artifacts/server`，包含前端 `wwwroot` 及 C# 伺服器。部署機器需要 .NET 10 ASP.NET Core Runtime，前端建置完成後不再需要 Node.js。

```sh
cd artifacts/server
dotnet ViewX.Server.dll --urls http://localhost:3000
```

## 功能與手動測試

- 檔案、編輯、檢視、畫面、元件、排列、變數、執行、說明選單。
- 一般畫面與 Popup 管理、多層母片繼承、起始畫面設定、18 種元件（含時間／日期、多狀態指示燈、刻度與表格）。
- 元件庫及「元件」選單依繪圖、靜態、按鈕、顯示、編輯五類分組；元件庫可收合類別，並依名稱、類別或英文種類搜尋。
- 拖拉、調整尺寸、多選、對齊、群組、圖層、鎖定、格線、復原／重做。
- 在空白畫布按住左鍵拖曳框選完整落入範圍的可見元件；Shift 框選追加選取，Esc 取消。群組元件一起選取，鎖定元件可選取但不會移動。
- 編輯模式右鍵點擊元件，開啟屬性視窗；修改即時套用，按完成、Esc 或點擊視窗外關閉，關閉後可復原。預覽／執行模式不開啟屬性編輯。
- 數值／布林／文字變數、資料綁定、顯示／啟用條件、模擬值監看。
- SQLite 專案保存、版本紀錄、版本衝突保護、JSON 匯入／匯出。
- Modbus TCP／COM RTU 設備設定、標籤位址映射、即時讀寫與重連，可接上 Word 警報與遮罩。

首次開啟會顯示尚未儲存的示範產線：按「執行專案」→「啟動／停止」，指示燈應改變；按「＋計數」，數值應增加。停止後新增元件、修改屬性、儲存，再從專案清單重開確認設定保留。

## 工程工作台介面

介面採灰階面板、矩形工具按鈕、緊湊分隔線與表格式屬性欄位，適合畫面規劃及設備監看。

- 上方元件工具列依繪圖、靜態、按鈕、顯示、編輯五類切換；支援點選插入與拖曳至畫布，分類頁籤可用方向鍵、Home／End 切換。
- 左側專案樹分開列出一般畫面與 Popup，可收合分支；提供設備通訊、標籤、全域警報及圖片資源入口。下方元件庫仍可分類搜尋。
- 右側「一般／外觀／資料／進階」提供屬性區段快速定位；依元件可用設定顯示按鈕。欄位保持在同一捲動區，方便連續設定。
- 中央畫面有視窗標題與尺寸／縮放資訊，下方全寬狀態列顯示選取、吸附、保存及執行狀態。窄螢幕將工具列與元件庫縮小，畫布可在自身區域捲動。
- 頂端狀態依實際編輯、離線模擬、等待設備、設備連線與通訊異常切換，通訊及警報管理可從工具列快速開啟。

工程介面樣式集中在 src/engineering.css，專案元件外觀與資料設定仍由元件／模型管理。

## 基本元件外觀設定

選取元件後可在右側屬性面板設定，或以右鍵開啟元件屬性視窗。修改即時套用並支援復原／重做，儲存後重開可保留設定。

| 元件       | 可設定功能                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------- |
| 文字       | 多行文字、字型、字型大小、粗體、斜體、底線、水平／垂直對齊、自動換行、行距、文字／背景色；可綁定變數顯示內容。 |
| 矩形／圓形 | 邊框顏色、線寬、實線／虛線／點線／無邊框、背景填色；矩形可調整圓角。                                           |
| 直線       | 線條顏色、線寬與線型。                                                                                         |
| 圖片       | 等比例完整顯示、等比例填滿裁切、拉伸填滿、原始尺寸裁切，及圖片對齊位置；可更換或移除圖片。                     |
| 按鈕       | 一般、滑鼠移入、按下、停用的背景／文字色；邊框、圓角與既有互動動作。                                           |

按鈕在預覽中可測試移入與按下外觀，停用狀態由「啟用條件（布林）」控制；停用時不執行動作。字型使用裝置上已安裝的字型，未安裝時使用替代字型。文字超出元件範圍會裁切；取消自動換行仍保留手動輸入的換行。

新外觀欄位為可選設定，既有 schema-v1 專案可直接開啟，不需轉換資料庫。

## 資料與互動設定

- **數值顯示**：小數、整數四捨五入、百分比、科學記號；小數位數留白時最多顯示 3 位，也可指定 0–6 位、千分位、前綴、單位及英文／臺灣／德文數字格式。百分比將原值乘以 100 顯示，0.125 顯示為 12.5%。
- **數值輸入**：可設定最小值、最大值與正數步距，留白表示不限制。步距起點為最小值，未設定則為 0。預覽時先編輯暫存文字，按 Enter 或離開欄位才寫入；Esc 取消。空白、非有限數值、超限或不符合步距時顯示原因並還原原值，不寫入變數。啟用條件為 false 時停用輸入。
- **變數綁定**：數值元件只列數值變數，指示燈／開關／切換動作只列布林變數；文字、設定值及重設動作支援三種類型。失效綁定、類型不符、條件或目標畫面失效會顯示診斷並阻止預覽／執行。
- **按鈕動作**：切換布林、設定數值／布林／文字、正負數加減、重設綁定變數為初始值、切換畫面。布林設定使用 TRUE／FALSE 清單；數字設定不能留白，也不接受 Infinity 或溢位結果。切換動作時自動挑選適用類型的變數，設定值動作更換綁定時使用該變數初始值，請確認設定值後再執行。

範圍與步距限制屬於各輸入元件，不是變數的全域限制；模擬值監看與其他按鈕動作仍可修改同一變數。專案檢查也確認輸入元件的初始值符合限制。可保存尚未完成綁定的專案草稿，預覽／執行前須修正診斷；欄位格式錯誤（例如步距為 0）則不能儲存。模擬互動只修改執行值，重新開始模擬時回到專案初始值。

## 進階元件

在元件庫新增「儀表」、「長條顯示」、「趨勢圖」或「警報清單」，再透過右側面板或右鍵屬性視窗設定。

| 元件     | 設定與行為                                                                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 儀表     | 數值綁定、量程、數值格式、資料／軌道顏色、警戒／危險門檻、顯示值與刻度；以半圓指針及弧線顯示。                                                                                  |
| 長條顯示 | 數值綁定、量程與門檻顏色，支援水平或由下往上的垂直方向。                                                                                                                        |
| 趨勢圖   | 數值綁定、Y 軸量程、顏色、100–60,000 ms 取樣間隔、10–600 個保留點；編輯時顯示示意曲線，預覽時依實際模擬值取樣。                                                                 |
| 警報清單 | 每個元件最多 20 項規則，支援數值的 >／≥／<／≤／=／≠ 比較及布林 TRUE／FALSE 條件；可設定訊息、資訊／警告／嚴重等級及規則啟用狀態。顯示筆數 1–100，支援「只看發生中」與逐筆確認。 |

儀表與長條達到警戒門檻顯示橙色，達到危險門檻顯示紅色。超出量程時圖形停在端點，數值仍顯示原值；趨勢線也限制在 Y 軸量程內。最大量程必須大於最小量程，門檻必須在量程內，警戒門檻不可大於危險門檻。

趨勢與警報會監看整個專案，切換畫面不會中斷取樣或遺漏該段警報。持續符合條件只產生一筆警報，條件恢復時標示「已解除」，再次觸發則新增一筆。確認只表示已閱讀，不會解除仍存在的條件。保留所有發生中警報及最近發生的最多 1,000 筆已解除紀錄。

預設資料源為本機模擬變數；設備連線模式使用已映射的 Modbus 標籤，未映射變數仍為內部值。趨勢點仍只保留在本次模擬；已儲存專案的全域及元件警報會另存SQLite歷史，停止、重新開始或還原專案版本不會刪除歷史。參照元件規則或全域警報區／遮罩的變數受刪除保護。

## Modbus 設備通訊

從「檔案 → 通訊設備與標籤」新增 TCP／RTU 設備，在「標籤映射」對應資料區及 **0 起算位址**，儲存後選擇「設備連線」並執行專案。設備 IP／COM 埠必須由後端存取；使用者端設備位於其他網路時仍需 VPN／路由或現場執行後端。

支援 Coil／Discrete Input／Holding Register／Input Register、16／32 位元整數及 float32、高低 Word 順序、倍率／偏移與讀寫權限。唯讀／失效標籤停用操作；設備寫入後讀回確認，寫入失敗不自動重送。設備資料失效時保留既有警報，恢復讀取後重新判斷。設定隨 JSON／SQLite 版本保存；連線工作階段及即時值不保存，也不會因載入專案而自動連線。完整欄位、API、限制及操作流程見 [Modbus 設備通訊規格](docs/Modbus-設備通訊規格.md)。

## 全域警報、跑馬燈與歷史

- 在「檔案 → 全域警報管理與歷史」管理警報區，或執行時開啟「執行 → 警報中心」。新增警報區會建立初始值為0的數值Word及遮罩變數，也可改綁既有數值變數。
- 每區使用16位元Word（0～65535整數），可維護Bit 0～15的訊息、資訊／警告／嚴重等級、啟用狀態與群組。檢查週期100～60000ms；目前採高準位觸發，持續為1只產生一筆，歸零後再為1才新增事件。
- 遮罩同樣為16位元Word，位元為1時抑制同索引警報。已發生的警報被遮罩時以「遮罩抑制」解除；移除遮罩但Word位元仍為1時會新增一筆。範例：Word=4觸發Bit 2，遮罩=4抑制Bit 2。無效的小數、負數或超過65535不會被轉成其他位元，介面顯示診斷。
- 專案可啟用上方／下方跑馬燈，輪播間隔1000～60000ms，依嚴重程度顯示所有發生中的全域與元件警報。支援降低動態效果的裝置設定；跨畫面切換仍持續監看。
- 警報清單元件可選「此元件規則」、「全域警報」或「全部警報」，並依群組篩選。既有元件預設維持自己的規則。
- 請先儲存專案再執行，以啟用歷史保存。未儲存專案仍能模擬，但介面會標示歷史未保存。發生、確認與解除的時間及原因、當時訊息／來源／群組／數值會寫入`alarm_events`；停止或重設會結束工作階段，尚未解除者標記「模擬結束」。正常離頁使用Beacon通知工作階段結束，瀏覽器強制終止或網路中斷仍可能留下未結束工作階段。
- 「歷史紀錄」可依訊息／來源名稱、等級、群組與發生時間查詢，50筆分頁，服務重啟後仍可讀取。歷史快照不隨後續規則修改而改變；JSON專案匯出包含設定，不包含事件歷史，備份完整歷史需備份SQLite。
- 保存採事件ID去重及逐批更新；失敗會保留待送資料並顯示錯誤，可手動重試，也會每5秒重試。待送資料在目前頁面的記憶體內，尚未建立離線磁碟佇列；有待送資料時離頁會提醒。請等待「警報歷史：已同步」後關閉。歷史目前不自動清除，長期使用須規劃資料留存。

## 對話盒與共通母片

- 在「畫面 → 新增對話盒」建立 Popup，或在畫面屬性／畫面設定切換「畫面類別」。一般畫面可設為起始畫面；對話盒不會取代起始畫面。
- 選取按鈕，將「互動動作 → 動作」設為「開啟對話盒」，再選擇目標 Popup；在對話盒內以「關閉對話盒」按鈕離開。右上角關閉鍵及 Esc 也可關閉最上層，模擬繼續執行。
- Popup 可巢狀開啟（最多 16 層，同一對話盒不可重複開啟），背景畫面及下層對話盒不能操作。切換一般畫面、停止或重設模擬會清除對話盒；預覽 Popup 時，它會顯示在專案起始畫面上方。彈出內容會依瀏覽器可用空間縮放。
- 在子畫面的「繼承畫面（共通母片）」選擇父畫面，一般畫面與對話盒皆可作父畫面，並支援多層繼承。父元件由最遠祖先至最近父畫面依序放在底層，子畫面元件位於上層；子畫面使用自己的尺寸與背景。
- 繼承元件會即時反映父畫面修改，不能在子畫面選取、拖曳、刪除或改屬性。右側圖層標示來源，點擊可到父畫面編輯；子畫面仍可新增及修改自己的元件。執行時繼承按鈕、輸入、趨勢與警報照常運作。
- 循環繼承會被拒絕；仍被繼承或按鈕引用的畫面不能刪除。繼承內容超出子畫面尺寸時，專案檢查會阻止模擬，請調整尺寸或父元件位置。
- 保存、版本預覽／還原與 JSON 匯入／匯出保留父畫面引用，不複製父元件。既有 schema-v1 專案無須轉換，未設定類別的畫面視為一般畫面。
- 既有 `screen`／`dialog` 類別、`inheritsScreenId` 母片引用及 `openDialog`／`closeDialog` 動作仍可使用；新介面也支援它們的預覽、編輯與還原。

「開啟對話盒」只開啟畫面；對話盒內的設值／增減按鈕各自立即執行。關閉動作不寫入變數，尚未提供將任意原按鈕動作暫存至「確定」後才執行的交易流程。

## 專案保存與資源管理

- **自動儲存**：在「檔案 → 專案設定」勾選「啟用自動儲存」，關閉視窗後生效。設定隨專案保存，預設關閉。停止編輯 2 秒後將快照保存至 SQLite；對話框開啟、執行模擬或資料格式未完成時暫停。儲存期間繼續編輯的內容仍會標記未儲存，並於下一次自動儲存保存。
- **錯誤與衝突**：自動儲存失敗時保留編輯內容並暫停，底部顯示狀態與重試按鈕。HTTP 409 代表其他分頁或使用者已保存新版本；可另存新專案保留本機內容，或匯出備份後重新開啟專案。重試不會略過版本檢查。自動儲存未完成前關閉頁面仍會提醒；目前沒有離線草稿復原。
- **版本紀錄與還原**：「檔案 → 版本紀錄與還原」列出每次手動與自動儲存的版本及時間，選取後可預覽各畫面。確認還原會取代目前編輯內容、重設復原／重做與模擬狀態，並建立新的版本。原有版本及當時圖片均保留；過期版本還原同樣受衝突保護。
- **圖片資源管理**：「檔案 → 圖片資源管理」可上傳、搜尋、重新命名、更換、刪除圖片並查看引用數。選取圖片元件後，可從資源庫套用圖片。相同圖片上傳會共用資源，更換圖片會同步更新所有引用元件；被引用的圖片不可刪除，需先移除或更換元件圖片。
- **既有圖片與備份**：「收集現有圖片」將舊專案元件內嵌圖片集中為共用資源。舊格式仍可開啟。JSON 匯出／匯入包含全部圖片，不依賴外部檔案；整個版本紀錄需備份 SQLite 資料庫。每個版本保留完整快照，圖片較多且頻繁儲存時資料庫會增長。

## 自動測試

```sh
npm run build
npm test
npm run test:server
npm run test:api
npx playwright install chromium
npm run test:browser
npm run test:widgets
npm run test:interactions
npm run test:advanced
npm run test:dev
npm run test:screens
npm run test:alarms
```

- `npm test`：前端 JSON 資料格式、數值格式、輸入限制、綁定及動作規則驗證。
- `npm run test:screens`：Popup 建立／預覽／巢狀關閉、背景操作阻擋、母片同步與編輯保護、循環繼承拒絕、SQLite 重開、版本還原與 JSON 往返。
- `npm run test:alarms`：Word Bit 0／15、遮罩／移除遮罩、跑馬燈、跨畫面監看、確認、服務重啟後歷史、查詢篩選與斷線重試去重。
- `npm run test:communication`：Modbus TCP API／瀏覽器讀寫、標籤保存、斷線重連、Word 遮罩與警報歷史；Linux 另用 Python 3／PTY 驗證 RTU 串列讀寫與 CRC。
- `npm run test:server`：C# 驗證器、SQLite 保存／版本及並行寫入測試。
- `npm run test:api`：以舊 Node.js 建立的 SQLite 檔案驗證 C# 讀寫相容性、重啟保存、驗證器一致性、HTTP 狀態、請求大小限制及靜態網頁。
- `npm run test:advanced`：四種進階元件設定／重開、量程與警戒色、跨畫面及有上限的趨勢取樣、警報發生／確認／解除／再觸發、模擬重設與無效設定檢查。
- `npm run test:interactions`：數值格式設定、綁定篩選、輸入確認／範圍／步距／取消／停用、各類按鈕動作、診斷與儲存重開。
- `npm run test:management`：自動儲存、圖片共用與刪除保護、版本預覽／還原、版本衝突暫停及資料格式檢查。
- `npm run test:widgets`：文字格式與變數綁定、圖形邊框、圖片縮放、按鈕停用／移入／按下外觀，以及設定儲存重開。
- `npm run test:browser`：透過 C# 後端實際測試編輯、模擬、儲存／重開、匯入／匯出及畫面切換。

`npm run test:dev` 另驗證 Vite 開發代理及前後端分開啟動時的儲存／重開流程。

整合與瀏覽器測試會自行啟動隔離 C# 服務並使用暫存 SQLite，不修改使用者的專案資料。可用 `VIEWX_BROWSER_PATH` 指向已安裝的 Chromium；若 `dotnet` 不在 PATH，可設定 `VIEWX_DOTNET_PATH`。

## 既有資料與設定

資料表、實體欄位、專案 JSON 欄位及保存／還原規則詳見 [SQLite 資料儲存規格](docs/SQLite-資料儲存規格.md)。

原本 `.data/viewx.db` **直接沿用**；`projects`、`versions` 資料表與 JSON 格式不變，不需要轉換或刪除資料。每次儲存會增加版本；過期版本寫入回傳 HTTP 409。圖片資源內嵌於 JSON，以 ID 共用，單張上限 3 MB，最多 100 張，請求上限 20 MB。

| 設定                  | 說明                                                                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `VIEWX_DB_PATH`       | SQLite 檔案路徑；預設為儲存庫的 `.data/viewx.db`，發布後為執行目錄的 `.data/viewx.db`。相對路徑依 C# 工作目錄解析，建議使用絕對路徑。 |
| `VIEWX_API_URL`       | Vite 開發代理的後端位置；預設 `http://localhost:5000`。                                                                               |
| ASP.NET Core `--urls` | C# 監聽位址，例如 `dotnet run --project server/ViewX.Server.csproj --no-launch-profile -- --urls http://localhost:5100`。             |

舊 Node.js 的 `HOST`、`PORT`、`NODE_ENV` 不再用於啟動後端。健康檢查仍為 `GET /api/health`，回傳 `{ "status": "ok", "storage": "sqlite" }`。

資料庫不納入 Git。備份應使用 SQLite Online Backup API 或關閉服務後備份；運行中不要僅複製 `.db` 而忽略 WAL 資料。發布產物不包含專案資料，部署時須保留／指向原有資料庫。

## 目前範圍

這是單人編輯與執行版本，已支援 Modbus TCP／RTU 設備通訊及警報歷史存檔。現場代理、伺服器持續警報／趨勢採集、非 Modbus PLC 驅動、多國語言、登入權限、多人協作、IndexedDB 草稿尚未實作。預設僅監聽本機，正式對外部署前需要身分驗證、HTTPS 與存取控制。

## 前端程式結構

`src/App.tsx` 只負責組合介面與提供編輯器 context，各項功能依職責拆分：

| 目錄                                  | 職責                                                                               |
| ------------------------------------- | ---------------------------------------------------------------------------------- |
| `components/widgets`                  | 18 種元件各自的 React 呈現與執行互動，透過 `WidgetRenderer` 統一呼叫。             |
| `registry/widgetRegistry.ts`          | 元件名稱、圖示、React 元件及建立函式的登錄表。                                     |
| `components/editor`                   | 工具列、選單、畫面編輯區、左側清單、屬性面板與檔案輸入。                           |
| `components/dialogs`、`components/ui` | 專案對話框及共用欄位、按鈕。                                                       |
| `hooks`                               | 選取／拖曳／縮放、復原／重做、模擬、快捷鍵、通知與專案保存；`useEditor` 協調流程。 |
| `context`                             | 將編輯器狀態與操作提供給各面板。                                                   |
| `services`                            | HTTP API、JSON 下載及專案檢查。                                                    |
| `types`、`utils`                      | 共用介面型別及專案複製、初始變數值。                                               |
| `model.ts`                            | 專案資料模型、預設元件及 JSON 格式驗證。                                           |

新增元件時，先在 `components/widgets` 建立獨立檔案，再加入元件登錄表。若新增元件種類或設定欄位，也需同步調整 `model.ts` 的型別、預設值與驗證、屬性面板及 C# `ProjectValidator.cs`；不需要將呈現程式加入 `App.tsx`。此拆分保留既有 JSON、SQLite 及操作行為。
